# 게임 규칙과 검증 결과

## 생산 규칙
"물품마다 생산에 가장 중요한 조건이 하나 있고, 그 조건이 5(매우 강함)인 나라는 한 번에 목표량만큼, 아닌 나라는 목표량의 1/4만큼 만든다."

| 물품 | 목표량 | 가장 중요한 조건 |
|---|---:|---|
| 쌀 | 20kg | 노동력 |
| 석유 | 20L | 자원 |
| 자동차 | 12대 | 자본 |
| 스마트폰 | 16대 | 기술력 |

| 나라 | 자본 | 자원 | 노동력 | 기술력 | 1회 생산량 (쌀/석유/자동차/스마트폰) |
|---|---:|---:|---:|---:|---|
| 가온국 | 2 | 3 | **5** | 1 | **20kg** / 5L / 3대 / 4대 |
| 나래국 | 3 | **5** | 1 | 2 | 5kg / **20L** / 3대 / 4대 |
| 다온국 | **5** | 1 | 4 | 3 | 5kg / 5L / **12대** / 4대 |
| 라온국 | 4 | 1 | 2 | **5** | 5kg / 5L / 3대 / **16대** |

학생 화면에는 능력치 대신 물품별 **생산 수준(4칸 막대)**과 생산량만 보입니다. 능력치와 특화 물품은 교사 화면에만 보입니다.

- 생산 기회: 나라마다 4번 (1차, 2차 각각)
- 확보율: 물품별 min(보유 ÷ 목표 × 100, 100), 종합은 네 물품의 평균
- 보유량과 확보율은 따로 관리. 목표를 넘은 물품은 창고에 남아 거래에 쓸 수 있음

## 설정 바꾸는 법
교사 화면 맨 아래 **국가·물품 설정과 규칙 검증**을 열면 나라 이름·색·능력치(1~5), 물품 목표량과 중요한 조건, 생산 기회 수를 바꿀 수 있습니다. 값을 바꾸면 그 자리에서 아래 검증 1·2를 다시 계산해 "통과/주의"로 보여 줍니다. 각 나라가 서로 다른 조건 하나만 5여야 수업 설계(1차 실패, 2차 성공)가 성립합니다.

기본값 자체를 바꾸려면 `js/logic.js` 맨 위 `DEFAULT_CONFIG`를 고칩니다. 나라 수를 바꾸는 것은 구조상 가능하지만, 지금 화면(무역 흐름도, 4칸 배치)은 4개국 기준으로 다듬어져 있습니다.

## 검증 결과

### 게임 규칙 (`node tests/verify.js`) — 모두 통과
- **검증 1. 1차 100% 불가능**: 나라마다 생산 조합 35가지 전수 + 순서까지 구분한 1,024가지 실제 실행. 어느 나라도 100% 불가, 최고 43.75%
- **검증 2. 2차 모두 100% 가능**: 특화 물품 4번 생산 + 실제 거래 함수로 6건 교환 → 네 나라 모두 100%
- **검증 3. 물품 보존**: 무작위 제안·수락·취소 2,000회 후에도 전체 합계 동일, 음수 재고 0건
- **검증 4. 조작 안정성**: 중복 요청, 빠른 연타, 같은 재고 동시 거래, 이미 성립한 거래 재수락, 당사자 아닌 나라의 수락, 단계 변경 중 수락, 새로고침, 2차 진입 시 초기화와 1차 기록 보존, 되돌리기

### 동시 접속 (`python3 tests/e2e_live.py`) — 17/17 통과
교사 창 1개 + 학생 창 4개를 띄워 전체 수업을 클릭으로 진행 (가짜 Firebase 사용):
방 만들기와 입장, 이미 고른 나라 막기, 접속 현황, 단계 변경 즉시 반영, 생산 버튼 연타, 새로고침 후 이어 하기,
동시 수락 경쟁(하나만 성립), 교사의 거래 취소, 네 나라 100%, 물품 합계 보존, 단계 변경 시 남은 제안 무효,
발표 화면, 자리 비우기 후 재입장, 시연 모드, 휴대폰 너비 레이아웃, 브라우저 오류 없음.

### 실제 서버 보안 규칙 (`/check` 페이지)
보안 규칙은 실제 Firebase에서만 동작하므로, 배포 후 `/check`에서 확인합니다. 학생이 방 만들기·단계 변경·창고 직접 수정·생산량 부풀리기·다른 나라 조작·1차 중 거래·남의 거래 대신 수락·수량 바꿔 수락을 시도하면 모두 거부되는지 점검합니다.

### 검증 5. 시간
전체 수업(생산 32회 + 거래 6건 + 단계 전환 7번)은 약 110번의 클릭이면 끝나며, 모둠당 30번 안팎입니다. 확인 창은 2차 시작·초기화·거래 취소 때만 뜹니다.
